# 上下文与画像维护

本次问题排查基于代码与模拟群聊回归测试，未读取服务器上的真实聊天记录。

## 重置上下文

原 WebUI 端点调用 GroupStateManager.ResetContextAsync，但该方法仅修改降级标记与重置时间，既未清空 HistoryStore，也未移除 Block C 读取的蒸馏摘要和群记忆。因此按钮返回成功后，下一轮仍会读取旧内容。

现在重置与工作流使用同一会话锁：等待当前请求结束，清空模型历史、群记忆与蒸馏摘要，同时清除上下文快照。旧后台蒸馏任务按会话版本及数据库重置标记检查，旧发送任务在发送前检查版本，避免过期内容重新进入上下文。其他群不受影响。数据库聊天归档及长期用户画像保留，聊天页仍可以回看旧聊天，这不表示模型上下文未重置。

## 说话人归属

发现的具体风险包括：同批不同人的引用合并到当前触发者引用中；机器人回显入历史时未标记 IsBot；无 mention 元数据时 @ 被渲染为统一的“用户”；用户标识只取前八位，存在同前缀碰撞。

现在各条合并消息分别保留其引用，当前触发者附件不会混入其他人的附件；按索引回溯的引用带原作者标识。机器人回显明确标记为机器人历史。@ 保留被提及者的标识，已知昵称附带相同的身份标识。长用户 ID 使用基于完整 ID 的十二位摘要标识，短 ID 保持原样；旧前缀标识仍可查询，但歧义时必须消解，不能任选一个人。

上下文明确区分发言人、被 @ 者、引用者和画像所属人。压缩记忆要求保留人物标识，禁止将他人的话或机器人发言当作个人事实。实际语言歧义仍需在真实群聊中观察，不能保证模型完全不误解。

## 自动画像

原实现只在发言时建档并累计消息数，画像内容依赖模型自主调用 update_user_profile。建档或互动八十次不等于已有兴趣、习惯等画像内容；没有独立的后台补建或刷新流程。

新增后台维护默认每五分钟扫描一次。最近四十八小时活跃、累计至少八条消息、存在至少三条本人近期发言，且没有画像内容或距离上次更新达到二十四小时的群友，参加补建或刷新。每群每轮最多两次模型请求，只提供该人的最近发言与已有画像，不混入别人的发言。没有充分事实时允许返回空结果，六小时内暂缓再次尝试；新增八条消息可提前重试。成功更新受 Profile.DailyUpdateLimit 限制，并使群友锚点缓存失效。后台结果不会覆盖其生成期间的前台新画像。

WebUI「配置 → 画像」可调整 AutoRefreshEnabled、AutoRefreshMinutes、MinActivityMessages、RefreshAfterHours。DailyUpdateLimit=0 会关闭后台更新。后台整理会增加少量模型调用，默认每群每轮上限为两次。

## 暂停机器人

WebUI「机器人」实例编辑区增加暂停开关，立即保存并持久化。暂停保持连接和消息记录，停止指令响应、链接直接回复、随机互动、对话回复、暖群发言与后台画像更新；发送前也会检查暂停状态。已发出的平台请求不能撤回。暂停不会重建网关连接，与禁用实例不同。

## /compact

管理员在当前群发送 /compact，即时调用模型将历史压缩为摘要，并保留 Context.DistillKeepMessages 条尾部历史。压缩与工作流串行，压缩期间到达的新消息按快照身份保留，不会被误删。无历史时直接提示；摘要为空、格式无效或模型调用失败时保留原历史。不启用降级，也不静默群聊。压缩的摘要进入后续 Block C，原聊天归档继续保留。
