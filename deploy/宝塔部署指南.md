# 宝塔服务器部署指南（Ubuntu + 宝塔面板）

## 前提

1. 在 [QQ 开放平台](https://q.qq.com) 创建机器人应用，开通群聊机器人能力：
   - 记录 **AppID** 与 **AppSecret**
   - 群聊场景需要申请「接收所有消息」权限（密度唤醒统计需要全量群消息推送；只开 @ 消息则被动触发可用、主动暖群不可用）
2. 注册 [DeepSeek 开放平台](https://platform.deepseek.com)，获取 **API Key**
3. 宝塔面板安装 **.NET 10 运行时**（或通过「网站 → .NET 项目」时按提示安装）

## 一、发布

在本机或服务器上执行（需要 .NET 10 SDK）：

```bash
cd "RainBot Agent"
dotnet publish -c Release -o publish
```

将 `publish/` 目录上传到服务器，例如 `/www/wwwroot/rainbot/`。

## 二、配置（两种方式任选）

### 方式 A：环境变量（推荐，凭据不进文件）

在宝塔 .NET 项目中设置，或在启动前 export：

```bash
export BOT__APPID="你的AppID"
export BOT__SECRET="你的AppSecret"
export RAIN__LLM__APIKEY="你的DeepSeekKey"
export RAIN__BOTOPENID="机器人在群内的OpenID（可选，见下）"
export RAIN__ADMINOPENIDS__0="你的OpenID"   # 首个管理员（可选，也可用 /admin 指令添加）
export ASPNETCORE_ENVIRONMENT="Production"
```

> **关于 RAIN__BOTOPENID（全量消息模式判断 @ 机器人用）**
> 开启「接收所有消息」后，官方推送的 `content` 已自动去除 @ 机器人前缀、`mentions` 也不含机器人自身，因此判断是否 @ 机器人需要机器人自己的 openid（兼容历史推送中的 `<@!{bot_openid}>` 标签）。
> - **不填也能用**：机器人被 @ 时（GROUP_AT_MESSAGE_CREATE 事件）会自动从消息中解析出自身 openid 并落库，之后全量消息即可精确判定；
> - 也可在群里用 `/admin set Bot.OpenId 你的openid` 手动设置（配置值优先于自动学习值）。

### 方式 B：配置文件

在 `publish/` 目录创建 `appsettings.Production.json`：

```json
{
  "Bot": { "AppId": "你的AppID", "Secret": "你的AppSecret", "UseSandbox": false },
  "Rain": { "Llm": { "ApiKey": "你的DeepSeekKey" }, "AdminOpenIds": ["你的OpenID"] }
}
```

## 三、宝塔 .NET 项目运行

1. 宝塔面板 → **网站 → .NET 项目 → 添加项目**
2. 项目目录：`/www/wwwroot/rainbot`
3. 启动文件：`RainBot.dll`，框架版本选择 net10.0
4. 绑定端口：`8080`（或按需修改，程序默认监听 `http://0.0.0.0:8080`）
5. 在项目设置中填入环境变量（见上）
6. 启动后访问 `http://服务器IP:8080/health` 验证：`{"status":"ok",...}` 表示 WebSocket 已连上

> 如果不用宝塔项目管理器，可用 systemd 代替（见文末）。

## 四、systemd 备选方案

`/etc/systemd/system/rainbot.service`：

```ini
[Unit]
Description=RainBot Agent
After=network.target

[Service]
WorkingDirectory=/www/wwwroot/rainbot
ExecStart=/usr/bin/dotnet /www/wwwroot/rainbot/RainBot.dll
Restart=always
RestartSec=5
Environment=BOT__APPID=你的AppID
Environment=BOT__SECRET=你的AppSecret
Environment=RAIN__LLM__APIKEY=你的DeepSeekKey

[Install]
WantedBy=multi-user.target
```

```bash
systemctl daemon-reload && systemctl enable --now rainbot
journalctl -u rainbot -f   # 查看日志
```

## 五、Docker 备选方案

```bash
docker build -t rainbot .
docker run -d --name rainbot --restart=always \
  -e BOT__APPID=... -e BOT__SECRET=... -e RAIN__LLM__APIKEY=... \
  -p 8080:8080 -v /www/wwwroot/rainbot-data:/app/Data rainbot
```

## 六、日常运维

| 操作 | 方法 |
| :--- | :--- |
| 查看日志 | 宝塔日志 / `journalctl -u rainbot -f` |
| 健康检查 | `GET /health` |
| 修改人设 | 编辑 `Persona/persona.md`（保存后自动热重载） |
| 热改参数 | 群里发 `/admin set 参数 值`（无需重启） |
| 一键静默 | 群里发 `/admin mute`（管理员） |
| 备份数据 | 拷贝 `Data/rainbot.db`（单文件，含画像/历史/配置） |

## 七、频控与合规提醒

- QQ 官方单群上限 20 qpm，程序默认按 15 qpm 限流并排队，**请勿调大**
- 主动暖群默认每群每小时 ≤ 1 次、密度唤醒 1 分钟 ≥ 10 条，避免打扰
- 管理员指令通过 `RAIN__ADMINOPENIDS__0` 或 `/admin admin add` 维护，机器人自我管理，与群管理员无关
